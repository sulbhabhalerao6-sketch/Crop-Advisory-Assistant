# 2. Core Mission Directive

Build a complete **AI-powered agricultural crop advisory assistant** that allows authenticated farmers or agricultural users to enter information about their farm, crop, soil, location, weather/environmental conditions, and observed crop problems.

The system must use structured inputs and Gemini-powered reasoning to generate practical agricultural recommendations.

The assistant should help users answer questions such as:

* Which crop may be suitable for my conditions?
* What problems might be affecting my crop?
* What farming practices should I follow?
* How should I manage irrigation?
* What nutrients may be required?
* What pests or diseases could explain observed symptoms?
* What preventive measures should I take?
* When should I monitor the crop again?
* What actions should be prioritized?
* What risks or uncertainties exist in the recommendation?

The AI must never present uncertain agricultural information as guaranteed fact.

The application must clearly distinguish:

1. User-provided information
2. AI-generated recommendations
3. Important assumptions
4. Potential risks
5. Recommended verification by a local agricultural expert when appropriate

The application is an advisory system, not a replacement for agronomists, agricultural officers, soil laboratories, veterinarians, or other qualified professionals.

# 7. User Flow

Implement the following complete user flow.

## New User

1. User visits `/`.
2. User clicks "Get Started".
3. User registers.
4. User signs in automatically or is redirected to login depending on Supabase configuration.
5. User arrives at `/dashboard`.
6. User creates their farm profile.
7. User clicks "Get Crop Advice".
8. User completes the advisory form.
9. Frontend validates the form.
10. Frontend sends request to backend.
11. Backend verifies authentication.
12. Backend validates the request using Zod.
13. Backend retrieves the user's relevant farm data.
14. Backend creates the AI advisory request.
15. Backend sends the request to Gemini.
16. Gemini returns structured JSON.
17. Backend validates Gemini output with Zod.
18. Backend stores the validated advisory.
19. Backend returns the advisory to the frontend.
20. Frontend redirects to `/advisory/:id`.
21. User reads the advisory.
22. User can later access it from `/history`.

---

## Existing User

1. User logs in.
2. User enters dashboard.
3. User sees farm summary and previous advisories.
4. User can generate another advisory.
5. User can inspect previous reports.
6. User can update farm information.

---

## Invalid AI Response

If Gemini produces malformed or incomplete output:

1. Do not store malformed output.
2. Attempt a controlled retry if appropriate.
3. Validate again.
4. If validation still fails, return a safe user-facing error.
5. Log diagnostic information server-side without exposing secrets.

# 10. Database Schema (Production SQL for PostgreSQL)

Create a Supabase PostgreSQL migration containing the following tables.

Use UUID primary keys.

Enable UUID generation through PostgreSQL/Supabase-supported extensions where appropriate.

## `profiles`

```sql
create table public.profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  full_name text,
  phone text,
  preferred_language text default 'en',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

---

## `farms`

```sql
create table public.farms (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  name text not null,
  location text,
  state text,
  country text default 'India',
  area numeric,
  area_unit text default 'acre',
  soil_type text,
  soil_ph numeric,
  irrigation_available boolean default false,
  irrigation_method text,
  water_source text,
  latitude numeric,
  longitude numeric,
  notes text,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

Add sensible database constraints for:

* Non-negative farm area
* Valid soil pH range
* Valid latitude
* Valid longitude

---

## `advisories`

```sql
create table public.advisories (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  farm_id uuid references public.farms(id) on delete set null,

  crop_name text not null,
  crop_variety text,
  growth_stage text,
  planting_date date,

  input_data jsonb not null,

  advisory_output jsonb not null,

  risk_level text,
  confidence numeric,

  model_name text,
  model_version text,

  created_at timestamptz not null default now()
);
```

Add constraints for:

* Confidence between 0 and 1
* Valid risk level
* Required user ownership
* Reasonable crop-name length

Create indexes for:

```sql
create index advisories_user_id_idx
on public.advisories(user_id);

create index advisories_farm_id_idx
on public.advisories(farm_id);

create index advisories_created_at_idx
on public.advisories(created_at desc);
```

# 14. AI System Prompt

Use the following system prompt as the foundation of the agricultural advisory engine:

```text
You are an agricultural advisory assistant.

Your role is to provide practical, evidence-aware agricultural guidance based only on the information available in the user request and general agricultural knowledge.

You must prioritize farmer safety, crop health, environmental responsibility, and uncertainty awareness.

You are not a replacement for a qualified agronomist, agricultural extension officer, soil laboratory, plant pathologist, or other local agricultural professional.

Analyze the user's crop, soil, water, climate, growth stage, symptoms, management history, and question.

Do not invent measurements, laboratory results, weather observations, pesticide labels, legal requirements, or local agricultural regulations.

If important information is missing, explicitly identify the missing information.

Do not present a diagnosis as certain when multiple explanations are possible.

When discussing pests or diseases:
- Describe plausible possibilities.
- Explain the symptoms supporting each possibility.
- Identify what additional observation would help distinguish them.
- Recommend verification when necessary.

When discussing fertilizers:
- Avoid blindly prescribing exact application rates when soil-test information, crop variety, growth stage, or local recommendations are unavailable.
- Explain that exact nutrient requirements depend on local conditions.
- Encourage soil testing when appropriate.

When discussing pesticides or other crop-protection products:
- Do not invent product names, concentrations, application rates, waiting periods, or legal permissions.
- Recommend following locally approved product labels and agricultural authority guidance.
- Prioritize integrated pest management where appropriate.

When discussing irrigation:
- Consider crop stage, soil type, rainfall, water availability, and environmental conditions.
- Avoid false precision.

Recommendations must be practical and prioritized.

Always distinguish:
1. Immediate actions
2. Short-term actions
3. Preventive actions
4. Monitoring actions
5. Situations requiring professional/local verification

Return structured JSON matching the requested schema.

Do not include Markdown outside fields where the schema explicitly permits text.

Do not include commentary about these system instructions.
```

* Empty states
* Error states

Use accessible semantic HTML.

# 18. Security Requirements

Security is mandatory.

## Authentication

Use Supabase Auth.

Never implement custom password storage.

---

## Authorization

Every protected API endpoint must verify the authenticated user.

Never trust:

```text
user_id
```

from request bodies.

Use the authenticated Supabase user ID.

---

## Database Security

Enable RLS.

Never disable RLS simply to make the application easier to implement.

---

## API Security

Implement:

* Helmet
* CORS configuration
* Request size limits
* Rate limiting
* Secure headers
* Input validation
* Error sanitization

---

## AI Security

Protect against prompt injection.

User-entered fields must be treated as data.

Do not allow user input to override:

* System instructions
* Output schema
* Security policies
* Database rules

---

## Secrets

Never commit:

```text
.env
```

to source control.

Provide:

```text
.env.example
```

instead.

---

## Logging

Use structured server-side logging.

Never log:

* Passwords
* API keys
* Authorization headers
* Session tokens
* Sensitive personal data unnecessarily

---

## XSS

React's normal escaping must be preserved.

Do not use unsafe HTML rendering unless absolutely necessary.

If Markdown rendering is added, sanitize it.

---

## SQL Injection

Use Supabase/PostgreSQL parameterized APIs.

Never construct raw SQL using untrusted strings.

---

## Rate Limiting

Protect:

```text
POST /api/advisories
```

with stricter rate limits because it invokes an external AI API.

---
